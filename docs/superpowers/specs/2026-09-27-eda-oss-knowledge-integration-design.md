# EDA Agent 的 OSS 资料检索接入

## 任务确认与边界

用户要求核对升级后的数据内容、可调用接口，并让原理图 Agent 从该数据源取器件、电路模块及 PCB 资料。改动范围限定为 EDA 专用的只读 OSS 检索适配器、已登录查询 API、Agent 提案中的资料引用、对应测试和文档；不改认证规则、PostgreSQL 表、OSS 对象、生产部署脚本或原生 KiCad 器件定义。

2026-09-27 只读清点：`ldcx-dataset` 有 286 个去重原始对象和 4 个处理对象、1 个原始 manifest，总计约 8.08 GB；`stark-lin` 为空。处理 manifest 记载 439 份文档、20,582 个片段，其中 402 份 `auto_approved_for_index`，37 份隔离。35 份 `schematics` 全为可检索的 PDF/文本资料，处理集没有 `.kicad_sch`、`.kicad_pcb`、符号或封装文件。抽查三个相关 ZIP 也没有原生 EDA 文件。处理 manifest 明确标注 `manualReview: false`、尚未发布给生产 Agent；因此它只能作为待复核资料，不能作为获批器件或可拖放模块。

本机通过标准 OSS API 对两个存储桶作了只读查询。提供的接入点从本机查询返回 `AccessPointNetworkTypeInvalid`；同一凭据通过标准 bucket endpoint 可读。上线前应由同地域 ECS 使用受限的只读身份和合适网络入口复测，不把提供的密钥写入仓库或浏览器。

## 方案选择

1. 每次提案直接读取 OSS 全文 SQLite 压缩包：对象约 52.8 MB，单请求耗时和内存不可控。
2. **采用**：服务端读取一个固定版本的处理 manifest 和约 6.9 MB 的 `chunks.jsonl.gz`，按 SHA-256 校验，在进程内缓存有界时间；只检索 manifest 允许建索引的来源。登录 API 返回有限条带来源标识、页码和截断摘录的结果，Agent 在生成提案前调用同一检索器。
3. 把资料导入 PostgreSQL：需要迁移、审核状态复制与索引运维；当前不需要。

配置由服务端环境变量提供，默认关闭。开启后缺配置、哈希不符或 OSS 失败均明确报错；不静默假装读到了数据库。模型上下文中的摘录被标记为未经硬件审核的外部资料，不能扩大当前 7 个官方 KiCad 器件的放置权限。提案和页面展示来源及审核状态，使用户能追溯资料。

## 原生器件与模块的独立发布门槛

文档检索不能产出可靠的引脚、符号、封装、PCB 焊盘与外部端口。后续真实模块须按 `docs/eda-module-contract.md` 提交版本化 KiCad 包，核对哈希、KiCad CLI/ERC/网表、端口和人工审核，再进入可放置目录。当前 OSS 对象不足以通过该门槛；本任务不会从 PDF 反推后自动注册一个“已验证模块”。

## 验证

- 真实 OSS：目录、manifest、片段/SQLite 的 SHA-256 与 SQLite `quick_check`；三类检索意图；隔离来源不进入索引。
- 确定性测试：manifest 和压缩包篡改、隔离来源过滤、相关性与结果长度、未配置/不可用状态、Agent 提案来源传递与现有器件范围。
- 构建、类型、定向回归；部署后才可声明公网 API 与真实模型检索闭环。

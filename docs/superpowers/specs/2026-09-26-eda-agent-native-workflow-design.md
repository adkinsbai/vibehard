# VibeHard 原生 EDA Agent 工作流设计

日期：2026-09-26。状态：用户已批准“已审核电路模块 + KiCad 原生候选版本 + FreeRouting + 立创/PDF 分级导入”的总体方向；本文把新增的 Agent 画图与改图验收要求落实为工程契约。本文记录目标和验收门槛，不表示这些能力已上线。

## 目标和当前事实

用户可以用自然语言描述电路，Agent 识别功能、供电、接口、约束与不确定项，选择团队已审核的器件/电路模块，生成可在自己的云端 KiCad 打开的原理图，并在后续对话中修改同一工程。候选版本必须保留无关电路、指出差异，通过真正的 KiCad 网表/ERC 检查，由用户审阅后发布。PCB 在同一原生工程中设计，自动布线产出待审阅候选板。立创 EDA 工程是可编辑工程导入来源；PDF 是需校对的重建证据。

当前线上只有七类受控官方器件，模型通过 `lib/server/eda-agent.ts` 返回最多 100 条平面 `EdaDocument` 编辑命令；服务器试算结构有效性，网页应用后创建**新** KiCad 文件。它没有真实电路模块目录、需求符合性判定、可恢复的多轮原生编辑、FreeRouting、立创/PDF 导入。线上基础 LED 请求曾生成三器件三网络并取得 ERC 0；这个事实不能证明“理解复杂需求”或“正确修改既有工程”。当前 KiCad worker 为 9.0.8。KiCad 9 的 IPC API 不提供原理图编辑插件；不能据 PCB API 推断原理图也可直接操作。

## 不变量和权限

1. 每个 `(账号, 工程)` 拥有自己的原生工程、版本和桌面。模型绝不直接写活动 KiCad 文件，也不将其他用户工程作为上下文。
2. Agent 工作始于**已保存**的完整工程快照及每文件 SHA-256。候选在私有暂存目录生成；接受前逐文件比较基线哈希。若用户继续在 KiCad 保存，候选必须重新基于新版本生成，绝不覆盖。
3. 已审核模块包不可变：`moduleId + semanticVersion + packageSha256` 唯一定位。项目版本钉住该三元组。未审核或缺失数据手册、符号/封装对应关系的包不进入“可生成”目录。
4. ERC/DRC 0 只是结构检查；电源裕量、绝对最大额定值、射频/高速规则、热、可制造性与真实功能分别记录证据，不能由 LLM 宣称通过。
5. “生成了原理图”仅在原生文件可打开、网表可导出且拓扑契约匹配后成立；“满足用户需求”还需要约束审查及用户确认。

## 模块包与端口契约

团队交付 ZIP 含 `manifest.json`、一份或多份 `.kicad_sch`、项目内符号/封装库和必要资料；PCB 设计块可选。manifest 含模块 ID、版本、每文件 SHA-256、来源/审核人/审核时间、KiCad 最低版本、功能说明、供电范围和电流预算、器件/BOM 来源、设计规则、端口。每个端口含稳定 ID、显示名、方向、信号种类、电压域、可连接/必连约束，以及唯一的 KiCad 层级引脚或内部网络映射。发布前在隔离工程中校验路径、哈希、符号和封装可解析、端口映射一对一、导出网表、ERC 报告；记录检查版本与豁免。一个采购来的 WiFi/蓝牙模块若只是一个器件，仍按器件入库，不能伪装为整块已审核子电路。

Agent 只接收审核后的模块元数据和可用端口，不直接复制/修改模块内部电路。组合器在候选工程中放置层级电路块并按端口连接，使用原生 KiCad 文件与库记录；扩展时不得把现有多页工程压扁成有损 `EdaDocument`。端口、电源域和规则不匹配时返回阻塞原因或待确认问题，不生成看似完整的图。

## 原理图 Agent 的工作流

1. **理解需求**：把原话保存为不可变输入，并抽取功能块、供电源/电压电流、接口/连接器、环境与成本/尺寸约束、交付物、明确禁止项。每个条目保留原句证据、置信度和状态（已知/假设/待用户确认）。
2. **找库并建立方案**：查询已审核目录及器件参数；生成系统方框图、模块实例、端口连接表、电源树和未覆盖需求。不得推测芯片引脚、封装、额定值。找不到可靠模块或遇到互相冲突的要求时先问一个具体问题；不得用通用占位器假装已交付。
3. **生成候选**：根据基线快照和约束生成有界操作/原生候选；所有新增实例、网络和端口有稳定 ID。先展示机器可读差异（新增、移除、改值、改网络、保留项）及人可读说明，再由服务端确定性执行。
4. **检查**：KiCad CLI 导出网表、BOM、ERC JSON 和可视化 PDF；以网表检查需求中的必须/禁止拓扑、电源域、必连端口及差异影响范围。非零 ERC 或豁免必须逐项解释；不能仅凭 ERC 0 推断意图正确。涉及 PCB 时再运行 DRC `--schematic-parity`。
5. **审阅和发布**：用户可在 noVNC 中检查候选工程与对照图。接受时再次验证源工程哈希并以新版本保存，拒绝保留原工程。下一轮改图沿用完整对话需求、锁定约束和父版本；默认只修改被请求范围，执行不相关网络/元件保持测试。

工作流由服务端状态机和校验器执行，不仅是一段提示词或安装到开发者电脑的 Skill。外部 Skill 可借鉴检查清单，经审核后转为版本化的项目规则；它本身不具备平台用户的工程权限。

## 现成工具的取舍

已核对的 [Ki-Stack](https://github.com/Milind220/Ki-Stack) 和 [KiCad schematic design Skill](https://github.com/Seahan1/kicad-agent) 提供工作流/审图清单，可提炼成版本化 Agent 指令；其安装到开发者客户端不会自动赋予 VibeHard 线上服务能力。[KiCAD-MCP-Server](https://github.com/mixelpixx/KiCAD-MCP-Server) 声称提供 KiCad 9+ 原理图编辑、ERC/DRC 和 Freerouting 工具，MIT 许可，值得放入**隔离副本**实测；接入前必须审查原生文件保真、路径权限、并发、失败回滚和许可证依赖。[Seeed KiCad MCP](https://github.com/Seeed-Studio/kicad-mcp-server) 适合参考网表/PCB 分析，其写图能力不能未经样本验证就承担生产写入。[Microsoft SchGen](https://github.com/microsoft/SchGen) 的语义连线中间表示可借鉴，但并非当前平台的直接替代服务。上述项目的 README 主张不等于本平台的实测结果；不把外部工具接入生产，直到同一评估集上的对照试验和安全审查完成。

## Agent 能力验收

评估集分三层并保留模型名、配置版本、提示词版本、模块包哈希、KiCad 版本、基线/候选哈希、原始输出、检查报告与人工裁决。

| 层级 | 必测内容 | 通过条件 |
| --- | --- | --- |
| 离线确定性 | 错误命令、同名不同网、遗漏端口、超出电压域、基线版本冲突、与要求无关的删改 | 校验器拒绝并指明具体约束；无源文件覆盖 |
| 真实模型基础 | LED 限流/连接器等当前库能表达的任务，含一次“把电阻改值但其他网络不变”修改 | 模型输出合法；原生文件打开、网表与参考拓扑一致；ERC 按任务预期；第二轮保持检查通过 |
| 审核模块场景 | ESP32 最小系统/通信模块等团队实际包，包含更换供电、增加外设、拒绝互斥要求 | 选对包版本和端口，满足必需/禁止连接；不确定时提问；人工工程师审图通过 |

每个任务的参考答案是**约束集合**而非唯一坐标图：必须器件/模块、必需和禁止的端口-网络关系、参数范围、ERC 上限、应保留集合。记录首试通过率、澄清适当率、修改保留率、工具调用失败率和人工裁决，按难度分桶；不能靠自评文字或 mock 把任务判为通过。模块场景必须等真实包入库后才可宣布验收。

## PCB、导入和服务边界

- 自动布线作业在独立副本上导出 KiCad DSN，以固定版本 Freerouting CLI 生成 SES，再导入板副本。强制超时/资源额度/并发上限，比较前后未连接数、其他 DRC、原理图一致性、封装/网络/板框保持；有劣化或基线冲突时拒绝接受。用户能查看并决定是否采纳。
- KiCad 完整工程 ZIP 保留多页、库和配置；立创标准版 ZIP、专业版 EPRO/ZIP 先走隔离暂存和 KiCad 9 官方 GUI 导入，用真实样本测格式覆盖后才建自动转换服务。ZIP 路径和文件大小受限；导入结果须比对器件、网表、封装和层数。
- PDF 存原件并逐页提取候选器件/引脚/网络，逐项带页码证据和不确定性；经人确认后重新生成 KiCad 工程。PDF 不宣称无损工程导入。
- 当前 2 CPU/7.4 GiB 主机运行最多三个 KiCad worker；Freerouting 首版单并发、排队与取消，只有实测后才调整。工程/模块包与候选版本存项目卷，不混入平台 release。

## 分期交付与可验收结果

1. **评估基线**：落地确定性拓扑/保留校验器、版本化任务集和真实模型运行记录格式；对线上既有 LED 能力重新测一次，并暴露不足。此阶段不声称复杂模块可用。
2. **模块目录与组合**：完成包契约、入库审核、设计块组合、完整原生候选与冲突检查；用团队首批真实模块通过“创建/二轮修改/用户打开”验收。
3. **PCB 自动布线**：DSN/SES 作业和差异审阅；真实双层板覆盖成功、失败、超时、取消和冲突。
4. **导入**：KiCad 工程和真实立创样本无损/有损差异报告；PDF 审阅式重建；回归不同账号隔离和多窗口保存。

## 依据与版本风险

- [KiCad 9 CLI](https://docs.kicad.org/9.0/en/cli/cli.html) 支持原理图 ERC、网表/BOM 导出与 PCB DRC；没有工程格式导入子命令。
- [KiCad IPC API 开发者文档](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/) 说明 KiCad 9/10 只支持运行中 GUI 与 PCB 编辑器插件；原理图插件在 KiCad 11 加入。平台使用 9.0.8，不能照搬较新版本 API。
- [KiCad 9 原理图手册](https://docs.kicad.org/9.0/en/eeschema/eeschema.html) 说明层级原理图、设计块和 ERC；[Freerouting KiCad 集成](https://github.com/freerouting/freerouting/blob/v2.4.1/integrations/KiCad/README.md) 推荐 DSN/SES 回环。
- [KiCad 9 工程导入手册](https://docs.kicad.org/9.0/en/kicad/kicad.html) 和[立创格式文档](https://prodocs.easyeda.com/en/format/index/) 是格式兼容性测试依据。
- [Espressif ESP32 原理图检查表](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32/schematic-checklist.html) 是首批 ESP32 模块的芯片专用审核依据；通用 ERC 无法替代此类厂商规则。

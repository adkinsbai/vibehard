# 云端 KiCad 工程隔离设计

日期：2026-09-25。状态：已按用户澄清的使用场景修订，待实施。当前 `/eda` 仍为本机单账号适配器，未部署此设计。

## 使用场景与边界

每个平台注册账号只编辑自己的工程。不同账号之间不共享 KiCad 桌面、工程目录、配置、连接票据或文件。产品不提供多人共同编辑同一个工程，也不需要协作接管、只读参与者、对象级实时合并。

隔离单位是 `(账号 ID, 工程 ID)`。同一账号打开两个不同工程时，它们各有运行中的 KiCad 桌面和文件目录。同一账号在多个浏览器标签页打开同一个工程时，标签页连接同一个桌面；刷新或断线后重新连接该桌面。所有该账号的标签页都可操作。它们看到的是同一鼠标、键盘焦点和 KiCad 窗口，而不是各自独立的编辑画布。原理图和 PCB 是同一工程桌面里的 KiCad 编辑器窗口。

## 现状与方案选择

当前 `services/eda-desktop/server.py` 用数据根目录的 `owner` 文件绑定一个账号；不同工程虽有不同子目录和虚拟显示器，进程仍以同一个 Linux 用户运行。`lib/server/eda-desktop.ts` 在生产环境禁用该适配器，`next.config.ts` 把 WebSocket 静态指向单一 broker。因此，去掉 `owner` 文件或增大会话数都不能构成云端隔离。

比较过三种实现：

| 方案 | 结果 |
| --- | --- |
| 单 broker、按账号分子目录 | 改动少，但进程共享宿主用户和文件权限；不采用。 |
| 每账号一个运行容器，容器内打开多个工程 | 账号边界清晰，但一个用户的多个工程共用进程资源和桌面生命周期；可作为将来优化。 |
| 每工程一个运行容器，由会话服务按账号和工程调度 | 账号与工程都隔离，重连和资源回收边界清晰；首版采用。 |

首版在云服务器上运行私有会话服务和按需启动的 KiCad 容器。容器使用固定版本的 KiCad、官方库和 TigerVNC；网页端继续使用 noVNC。容器以非 root 身份运行，只挂载该工程的持久数据卷；`HOME`、KiCad 配置、X display、临时目录和进程空间随容器独立。容器设置内存、CPU、进程和磁盘限额。宿主的容器控制接口不暴露给 Next 网页进程或浏览器。

## 请求、文件和生命周期

1. 浏览器向现有同源工程 API 请求启动或连接；Next 校验登录态与 `ownedProject`，从服务端确定账号 ID 和工程 ID，浏览器不能自报归属。
2. 私有会话服务以 `(账号 ID, 工程 ID)` 查找或启动唯一运行实例，返回短期、单次使用、绑定该实例的连接票据。多个 Next 或网关副本运行时，票据和会话映射存放在共享状态存储，而非单进程内存。
3. 浏览器经同源 WebSocket 网关提交票据；网关重新验证浏览器登录态，并核对票据中的账号、工程和实例，再转发到目标容器的私有 VNC 端点。容器地址和 VNC 端口不公开，WebSocket 不依赖构建期静态重写到某一个 broker。
4. 原生 `.kicad_sch`、`.kicad_pcb`、`.kicad_pro` 及工程内库文件保存在该工程专属持久卷。重连、空闲关闭和服务重启不重置已保存文件。断电前尚未保存的 KiCad 内存状态不承诺恢复。
5. Agent、ERC、DRC、下载与制造文件生成先从**已保存**文件取得一致的只读快照，并记录源文件清单与哈希；快照复制期间源文件变化则重试或报错，不发布混合版本结果。Agent 写入须走受控的新版本/差异确认流程，不直接改用户未保存的 KiCad 窗口。
6. 空闲运行实例按配置关闭，活跃或待启动请求受全局和账号级配额约束。容量不足时明确排队或返回可重试状态，不把新账号路由到别人实例，也不静默丢失已保存工程。

工程卷的实际宿主路径由平台服务端根据数据库工程标识解析；API、浏览器和 Agent 不拼接服务器绝对路径。EDA 文件与平台 release、Runner 会话状态分离。需要供 Runner 使用时，通过受控的工程版本导出/挂载接口交付，而不是开放宿主文件系统。

## 故障与安全约束

- 每次控制 API 和连接票据签发都重新校验登录及工程归属；直接请求别人的工程 ID 返回不可区分的拒绝结果。会话服务只接受内部认证请求，不能仅凭 URL 中的账号 ID 授权。
- 票据过期、重放、跨工程使用、跨账号使用都失败；断线后可重新签发。停止工程只停止该工程的实例，不能停止其他账号或工程。
- 容器崩溃后回收残余进程、端口和挂载，再从已保存工程卷重建。快照、检查或下载失败要返回实际错误，不能给出旧结果。
- 已保存文件有备份/版本恢复机制；升级 KiCad 镜像前验证版本兼容，不能在自动重连时隐式改写工程。
- 现有本机单账号 broker 保留为开发适配器，云端路径单独实现并验收，不能通过移除 `owner` 检查将其直接上线。

## 验收与交付顺序

1. 先完成容器镜像、私有会话服务、工程卷与资源限额；用隔离测试工程验证容器停止和重启后的已保存文件哈希一致。
2. 接入现有 Next 工程权限 API 和同源 WebSocket 网关；验证票据签发、消费、过期、重放和错误显示。开发本机路径继续工作，生产路径有独立配置。
3. 在目标云服务器测量资源后，至少验证三个不同账号各自打开并编辑一个工程，同一账号并行打开两个不同工程、同一工程两个标签页重连，以及跨账号访问全部拒绝。随后验证保存、断线、服务重启、ERC/DRC 和 ZIP 只使用该工程已保存文件。容量不足时先调整主机资源或并发配额，再考虑发布。

上述验收未完成前，不称云端 KiCad 多用户可用；本设计不包含生产发布授权。

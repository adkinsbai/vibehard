## 入口与权限

用户入口为 **Agent 项目 → 选择项目 → 项目知识库 · 审核与版本**，页面路径 `/vibehard/app/agent/<projectId>/knowledge`。原理图申请成功后可直接点击「查看申请与审核状态」。

已上线的新规则取代此前“所有者自行审核”的决定：

- 普通项目所有者只能创建、编辑和恢复本项目草稿，查看审核状态；不能发布、退回或停用。
- `admin` / `developer` 可通过 **平台管理 → 知识库审核**（`/vibehard/app/knowledge-review`）查看跨项目资料并审核。管理概览也提供链接。列表按项目分页，每页最多 10 个项目，仅返回知识条目元数据。
- 审核者不能编辑他人的草稿，需退回由所有者修改；不能由此读取他人的工程目录、文件或聊天。已发布资料依然只供原项目使用，不自动变成全平台共享知识。
- `developer` 不获得管理员模型 Key 设置、密码重置、平台概览等权限。新注册用户仍为 `member`，不接受注册请求指定审核角色。本轮未给任何账号升权，也未新增自助角色设置入口。
- 所有读写在服务端查当前持久化角色，不能依赖 Cookie 中角色或隐藏按钮。数据库写操作在事务内重新查角色并锁定，防止与降权并发。

## 资料生命周期

1. 粘贴文字、导入 `.md/.txt` 或原理图分析模块提交结果，均创建待审核草稿。
2. 管理员或开发者核对原始来源、引脚、电平及待确认项，勾选确认后发布正式版本；也可填写原因退回，所有者编辑保存后重新进入待审核。
3. 编辑只更新草稿，不改变已发布版本。再次确认发布，生成新的版本号、审核人、时间和 SHA-256。
4. 停用不删除历史；恢复历史版本只是复制为草稿，仍需重新审核发布。
5. 修改/审核操作带 `expectedRevision`；并发编辑或重复审核返回 409，界面保留未保存输入，不静默覆盖。退回只影响当前草稿，不自动撤销旧正式版本；需要撤销时由审核者显式停用。退回原因记录在当前状态及数据库审计中。

权限调整不删除旧正式版本，也不伪造它们的审核人。本次上线前只读盘点：由非管理员/开发者发布且仍生效的资料为 0，无需修改正式资料。这不是强制双人审批，拥有审核角色的人仍能审核自己项目的资料。

“审核通过”仅表示可作为开发参考，不意味着已上板、引脚正确或硬件验收通过。资料必须保留不确定项及来源。

## Agent loop 接入点

`网页提交任务 → 所有权检查 → 数据库事务固定正式知识快照 → runner_commands.task.start.knowledge → Runner 校验 → turn/start 参考资料 → 事件清单/执行报告`

- 资料存 PostgreSQL `project_knowledge`，一个项目一份有界 JSONB 资料集。不是把文件写进 release、Runner 状态目录或任意服务器路径；首版也不复制到 workspace。
- 排队任务的完整知识快照保存在命令 payload。发布/停用与任务快照使用同一项目事务锁；排队后再修改不改变该任务快照。
- 只加载正式版本，不读取草稿；最多 20 份、单份正文 6000 字、正式正文合计 24000 字。每份最多 20 个已发布版本，含历史的项目资料总 JSON 不超过 1 MB。达到上限拒绝，不自动删除历史。
- JSON API 请求限制 64 KB；浏览器文本文件限制 32 KB。不解包、不下载来源 URL、不解析 PDF、不执行正文或启动模型索引。
- Runner 必须声明 `project-knowledge-v1` 且数据库心跳不超过 90 秒，否则含正式资料的任务返回 409。心跳检查并非活动连接或模型成功的证明；真正发送仍由 Gateway 的活动连接完成。
- Runner 验证快照/资料哈希，把正文作为低信任参考数据传入模型；可信规则禁止把资料里的指令当成执行授权。已有只读沙箱和人工工具审批保持不变。提示词边界不是绝对的 prompt-injection 防护。
- 将新快照与该网页会话最近 `task.started` 的知识 hash 对比；变化或停用全部资料时不恢复旧原生模型会话，而创建新上下文，避免沿用已撤回资料。网页聊天仍保留，但旧聊天不会自动带入新模型上下文；用户应写全新任务需求。
- `task.started` 和终态事件记录标题、版本、哈希及上下文重建标记；工程工作流报告追加同一清单。清单不是模型确实引用、理解或验证资料的证明。
- 不在本轮实现向量检索、文件上传存储、PDF 分析、全平台共享知识或 Agent 自主发布。

## 给原理图分析模块的接入契约

9/20 已上线：原理图页已接真实识别与「申请加入知识库备选」按钮，详见 [原理图备选流程](schematic-knowledge-candidates.md)。经验 Markdown 经 Agent 整理的专用通道仍待做。

真实分析完成后，在当前登录用户选择的目标项目下调用：

```http
POST /vibehard/api/projects/<projectId>/knowledge
Content-Type: application/json
```

```json
{
  "action": "create",
  "draft": {
    "kind": "schematic",
    "title": "泰山派原理图功能引脚分析",
    "source": "原始文件名.pdf；修订版；页码；可选文件 SHA256",
    "content": "功能引脚、证据页码、默认状态、待确认项、分析局限。不要把猜测写成已验证。"
  }
}
```

沿用同站登录 Cookie 与服务端所有权检查，不传服务器绝对路径，不使用管理员/Runner 密钥。不应自动调用 `publish`。保存成功返回 `{documents,publishedCount}`，可跳转到项目知识库页面提示工程师审核。

新版 create 可附 `submissionId`（唯一分析 UUID）保证同一项目内重复申请不再建档；同一编号内容不一致返回 409，后续审核/编辑不会被重试覆盖。已随 9/20 平台部署。重跑不同分析可创建新备选；若要更新已有草稿，使用 `action: edit`、`documentId`、`expectedRevision` 与 `draft`，发生 409 需人工协调，不盲目覆盖。

人工审核发布请求为 `{action:"publish",documentId,expectedRevision,confirmed:true}`。`confirmed` 是界面确认契约，不是独立工程师签名或强制双人审批。

其他动作：审核者使用 `disable` 停用或 `{action:"reject",documentId,expectedRevision,reason}` 退回（原因 1–1000 字）；所有者使用 `restore-draft` 加 `version` 复制历史为草稿。GET 同路径返回资料、项目名称与 `permissions:{canEdit,canReview}`。GET `/api/knowledge/review?after=<project UUID>` 返回审核列表及 `nextCursor`，普通成员 403。错误：401 未登录、403 角色/所有权不足、400 格式/容量、409 版本冲突、413 请求过大。

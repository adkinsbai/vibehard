# 原理图识别 → 知识库备选

2026-09-20：已随 `20260920-knowledge-review` 部署，申请与平台审核分权已生效。模型调用验收与当前波动详见 `current-status.md`。

## 两种资料来源

1. 网页上传原理图，真实模型生成带来源/待确认项的分析 Markdown，由用户选择项目并申请进入备选；本轮实现。
2. 既往板卡开发经验 Markdown，由用户/开发者/管理员提供，先经 Agent 整理（板卡及版本、前提、操作、验证证据、失败原因、可复用结论、未知项），再进入备选；本轮未实现这个专用处理通道。现有知识页的手工草稿/MD 导入仍存在，不应误称为已经自动经 Agent 整理。

“备选”就是项目内待审核草稿。9/20 新规则：用户只能申请，只有平台管理员或开发者显式审核发布才进入 Agent 的正式快照；不新增全平台公共知识库或自动发布。审核角色只能跨项目查看和审核知识，不能编辑他人草稿或读取其聊天/工程。

## 用户点击位置

1. 左侧「原理图识别」，上传 PNG/JPG/PDF，勾选有权处理且同意发送模型服务，点击「开始识别」。
2. 成功后的「识别结果 · 待审核」区域右上角可「下载识别文档 MD」。正文下方是「申请推送到知识库备选」。
3. 在「目标项目」下拉框选择自己拥有的项目，点击「申请加入知识库备选」。仅识别本身不会写入项目知识库。
4. 成功后点击「查看申请与审核状态 →」，直达该项目、该草稿。普通所有者可修改后保存，但看不到发布按钮。
5. 管理员或开发者进入左侧「平台管理 → 知识库审核」，选择资料，核对原文件后勾选确认并点击「审核并发布」，或填原因「退回修改」。这是单独权限与动作，不在申请按钮中执行。

用户没有项目时提示先创建项目；项目获取失败可重试，不把失败当成空列表。识别失败不提供申请按钮，不回退固定 STM32 示例。更换文件或重新识别清除旧结果；提交期间不能换文件/项目。下载内容包含标题、来源与同一份完整正文；以纯文本渲染，不执行 Markdown 内 HTML。

## 后端和数据边界

- `POST /api/schematic`：沿用登录认证，限每用户每分钟 3 次、每用户最多 1 个进行中任务、每个平台进程最多 2 个。部署多进程时这些限制不共享，需另建全局配额。
- 文件本体最多 5 MiB；先限流读取 multipart 请求总字节，再解析，验证文件魔数、扩展名/MIME。不是完整文件安全扫描。文件不执行、不保存到磁盘/OSS/数据库；只在内存转发到管理员当前配置的服务商。原图由用户自行留存，不能仅靠哈希还原原文件。
- 暂共用 `design`（硬件方案生成）模型配置，不改变现有模型或 Key。Responses 的 input_image/input_file 与 Chat Completions 的 image_url/file 格式已接入；服务商兼容性必须实测。没有配置、限流、格式错误、超时或不支持附件时明确报错。
- 输出 Markdown 最多 5500 字，再由服务端加入待审核声明（知识正文上限仍 6000 字）。来源由服务端填写原文件名、SHA256、模型、时间和唯一分析编号。来源是追溯提示，不是不可伪造的签名证书；项目所有者本来就能编辑草稿。
- 无工具模型提取要求区分事实/推断/未知，注明页码/区域/位号，不补全不可见引脚、不声称 ERC/上板通过。这是提示词约束，不是识别正确性保证。
- NDJSON 心跳 10 秒、模型超时 90 秒，浏览器最长等待 110 秒，支持取消。无自动循环重试或后台模型批处理。
- 申请复用 `POST /api/projects/<id>/knowledge` 的 create：附 `submissionId=analysisId`。服务端在现有项目事务锁内去重，保存原始提交摘要，同一编号/内容重试不重复建档，也不覆盖后来编辑/审核状态；编号复用不同内容返回 409。无新 SQL 表或迁移。
- 草稿提交/编辑仍要求项目所有权，publish/reject/disable 仅允许管理员或开发者。审核后才进入知识快照；原理图模型不直接触发云端工程 Agent，不使用任何设备/烧录工具。

## 验证

- 9/20 发布：101 项常规 + 3 项隔离 PostgreSQL 测试、候选 HTTP 权限与资料生命周期、正式/公网前端保护通过。VibeHard nginx location 上传上限设为 6 MiB，保留应用 5 MiB 限制；采用保持原 inode 的配置写入和 `nginx -t` 后平滑 reload，无容器重启。公网超过 5 MiB 的请求到达应用并返回 JSON 413（非 nginx 拦截）。约 1.1 MB 及 <2 KB 合成 PDF 两次真实模型请求均 90 秒超时，未获得草稿，不能据代码上线声称识别稳定可用；浏览器连接工具超时，未完成点击全流程。

以下为 9/19 开发期历史验收：

- 95 项常规测试通过；3 项数据库专用测试本轮未重跑（前次知识库部署曾在临时库通过）。类型、针对性 lint、Next 生产构建、服务构建通过。
- 新测试覆盖实际附件字节和两种协议格式、流式超大输入、伪造格式、登录/配置、失败无假结果、并发/取消释放、草稿且不发布、跨用户拒绝、重复申请保留后续审核、UI 目标选择/网络重试/直达审核和显式确认。
- 云端只读加载现有 `design` 配置，用临时验收脚本发送一页人工构造的微型 PDF；`gpt-5.6-sol` / Responses 36.753 秒返回随机唯一标识、R7 与 D2，并指出图中 LED 符号/极性/地连线不完整。证明该次真正读取 PDF，而非固定回复；不是泰山派完整原理图精度验收，也不是浏览器端到端上线验收。未写正式项目/账号/知识资料、未改服务。
- PNG/JPG 目前有协议及上传合约覆盖，未做真实服务商图像请求；复杂多页 PDF、加密 PDF、超时服务商和正式网页大文件上传仍需上线前验证。
- 部署前确认 nginx 允许带 multipart 开销的 5 MiB 请求、关闭代理缓冲且允许等待；旧 Gateway/Runner 无需为此功能更新。需候选版本端到端验证、确认空闲、保护 PCB/Demo，不能因本地完成直接修改 active release。

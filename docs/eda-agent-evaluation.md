# 原理图 Agent 可重复验收

这套评估针对现有受控器件目录与 `EdaDocument` 命令链。它检查 Agent 能否把一句需求转成真实元件与引脚网络，并在后续指令中保留未要求修改的电路。离线单元测试只证明评估器会发现错误，不证明模型画图能力。

## 运行真实模型测试

在已配置平台设计模型与 KiCad CLI 的受控开发环境中运行：

```sh
pnpm exec tsx scripts/evaluate-eda-agent.ts --runs 3
```

每次运行从新的内存空白工程开始，依次执行三轮任务：5V 指示灯串联电路、将限流电阻调整为 1 kΩ、保留原支路并新增第二个并联指示灯支路。每轮都实际调用 `proposeEdaEdit`，应用模型返回的命令，再调用 KiCad CLI ERC。输出 JSON 包含每次运行、每轮的模型名、命令数量、意图检查、旧电路保留检查和 ERC。任何一次运行失败，进程以非零状态结束；依赖前一步的后续轮次不再执行。报告不包含 API 密钥。

每次执行会在被 Git 忽略的 `.eda-data/agent-evaluations/run-*` 创建私有目录，并保存 `report.json`。报告记录场景版本、整个场景与提示词的 SHA-256、KiCad CLI 版本，以及模型对每轮修改的文字解释。只要模型返回了提案，每轮都会先保存带基准文档、原始受控命令、模型解释和哈希的 `*-proposal.json`；即使随后拓扑或 ERC 判定失败，也能复核模型实际做了什么。每次执行 ERC 都会保存同一原生 `.kicad_sch`、KiCad 直接写出的原始 `*-erc-raw.json`、退出码、哈希与 `*-erc-evidence.json` 元数据；没有执行或没有报告时明确记为空。通过内存约束与 ERC 的候选，再由 KiCad CLI 从同一份原理图导出 `.net`，解析实际 `ref.pin→net`，与全部意图约束及草稿拓扑比对。原生网表不符会使该轮失败，差异留在私有报告中；网表文件及其 SHA-256 仍保留供复核。默认控制台只打印结果摘要、证据路径与哈希，不打印电路文件、提示词、模型解释或密钥；目录应只向授权工程师开放，尤其是将来使用真实用户需求时。在 Linux 上目录和文件分别按 `0700` 与 `0600` 创建。

运行报告中的 `execution: live-model-attempt` 只表示尝试执行真实链路。只有 `modelRequestsSucceeded` 与 `nativeErcExecuted` 均覆盖实际执行轮次时，才有真实模型加原生 KiCad 证据。本地未配置设计模型时会在第一轮如实失败，不会使用预制模型答案替代。

评估器收到模型文本后，会先在私有证据目录保存限额 1 MiB 的 `*-model-raw.txt`，因此 JSON 解析或命令校验失败也能复核原始回复。`modelResponsesReceived` 是收到的原始回复数，`modelRequestsSucceeded` 是通过提案解析的轮次数。原始回复可能包含电路需求或其他敏感内容，不应上传到公开 PR、公开 CI 日志或共享目录。

## 判定规则

| 层次 | 判定依据 | 能发现的错误 |
| --- | --- | --- |
| 命令 | `parseEditBatch` 与 `applyEditBatch` | 无效命令、旧版本冲突、未知器件/引脚 |
| 意图 | 器件类型/数量/参数、指定引脚同网、不同连接组异网、指定两端异网 | 缺元件、阻值不符、LED 极性颠倒、限流电阻被旁路、5V 对地短接、额外器件 |
| 修改保留 | 旧器件身份与未授权参数、旧引脚间的连接关系 | 修改其他元件、断开旧线、误把两个旧网络合并 |
| KiCad | 原生 CLI 导出后的 ERC 报告 | KiCad 能识别的电气与网格错误 |
| 原生网表 | KiCad 从同一 `.kicad_sch` 导出的器件库身份、封装、参数与引脚网络 | 导出语义偏离内存草稿、漏线、反接、意外短接、替换符号或封装 |

所有层次都要通过。ERC 为 0 不能证明符合用户意图，例如将两个无源 LED 引脚接反仍可能通过 ERC。纯拓扑判定也不能证明电路的电压、电流、热设计、器件料号或可制造性；这些仍要按 datasheet 与设计评审核查。模型解释是否充分、版面是否清晰也需要人工审阅真实 KiCad 文件。

测试场景固定需求与判定规则，不固定模型命令、元件 ID、网络名称或摆放位置；可以重复运行并统计同一规则下的成功次数。现有目录只支持少量官方 KiCad 器件，当前场景代表基础能力，不能外推至 ESP32 最小系统或用户将提供的电路模块。模块到位后，应增加端口连接、电源域、复位/启动约束、修改保留和模块版本追踪场景，并以人工审核过的原生 KiCad 工程作为对照。

## 当前证据边界

离线单元测试已验证反接、漏线、短接、限流电阻旁路、参数错误、异常 ERC 报告、单引脚网遗漏、符号/封装替换，以及原生网表与内存草稿不一致时整轮失败。当前 EDA 定向测试 97 通过、2 跳过，类型检查、定向 lint 和带 `/vibehard` basePath 的生产构建通过。另用本机 WSL 中真实 KiCad 9.0.8 从固定 LED 测试原理图导出 `.net`，新解析器判定 `passed: true`；该烟测工程 ERC 仍有 3 项网格错误，因此这只是原生格式兼容证据，不是模型画图通过证据。Windows 进程当前没有直接可执行的 `kicad-cli`，正式重复测试应在已配置设计模型和 KiCad CLI 的 Linux/云端环境运行。当前本地真实入口因设计模型未配置在第一轮结束，模型成功请求数与 KiCad ERC 执行数均为 0，提案与制品清单均为空。线上 2026-09-26 的单轮 LED 电路验收记录见 `docs/eda-cloud-acceptance-2026-09-26.md`，但它不是本三轮场景的通过结果。

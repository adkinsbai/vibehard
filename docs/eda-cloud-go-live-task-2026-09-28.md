# EDA 云端闭环与正式发布任务确认

日期：2026-09-28。用户要求并行完成原生模块、AI 原理图、KiCad/FreeRouting PCB 候选及线上多用户使用，并以四小时为交付窗口。用户明确选择“正式硬件设计可用”作为对外发布标准，并要求在首个原生模块经工程师审核后再发布。

## 本轮允许的改动

- `services/eda-desktop/**`：为每位用户/工程隔离的 KiCad worker 增加异步布线任务、状态和候选板读取，保留原工程。
- `app/api/eda/desktop/[id]/route.ts`、`lib/server/eda-desktop.ts`、`components/eda/desktop-workbench.tsx` 及相关样式/测试：在网页发起、查看、验收布线候选；接受候选时新建用户自有工程。
- `lib/eda/module-package.ts`、`lib/eda/modules.ts`、`lib/server/eda-agent.ts`、模块目录/审核 API、数据库迁移及相关测试：原生模块包入库、校验、独立审核、发布及 Agent 的已发布目录。
- 本任务文档、测试与验收记录、`.ai/TASK_LOG.md`、`.ai/PROJECT_STATUS.md`。

高风险区域中的认证、租户隔离、数据库迁移和生产部署，已由用户对本次完整云端闭环与上线工作的明确要求授权；仍须采用现有权限/审计模型、版本化发布流程和测试。不得直接修改生产 release、数据库或其他用户工程。

## 正式发布门槛

1. 至少一个原生模块包的元数据、端口、原理图、PCB、料号/封装/电气参数由硬件工程师审核并留下可追溯记录。软件样板只证明链路，不能充当该模块。
2. 服务端只允许审核发布的模块进入正式 Agent 目录；Agent 生成和修改的成果须有 KiCad 原生文件、ERC、PCB DRC 及可追溯来源。结构正确不能替代工程安全或制造审核。
3. 云端实际执行 FreeRouting DSN/SES 往返，验证源工程未变、候选差异与 DRC、失败/超时、至少两个用户工程隔离和候选接受后的新工程归属。
4. PR 完成评审并入库后，由发布负责人走版本化 release、预检与回滚路径；上线后用普通新账号复测。部署访问不通时保留交付包和证据，不能称已上线。

时间窗口只约束推进和报告，不降低上述发布标准。缺少模块审核、生产访问或验证证据时，明确标记为候选待发布。

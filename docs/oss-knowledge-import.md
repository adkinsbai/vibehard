## 存储边界

```text
浏览器/本地导入器 --分片直传--> 私有 OSS 原件区
                              |
                              v
                     上传清单与隔离审核队列（PostgreSQL）
                              |
                    受限后台解析 / OCR / 去重 / 切分
                              |
                  已确认正文与检索索引（独立、有界）
                              |
                     管理员/开发者审核发布
                              |
                  方案 Agent 仅检索已发布的可见资料
```

- **OSS 存原件**：首阶段目标是现有 Store Dataset Bucket 的独立 `knowledge/raw/v1/` 前缀，按随机批次 ID、资料 ID、内容哈希生成 Object Key；对象 Key 由 `knowledgeRawObjectKey()` 生成，不包含 Bucket 名或用户文件名。使用前仍须实测 Bucket 私有性、地域与前缀隔离；目录名不作为权限或可信分类依据。服务端不把 8 GB 代理进 Next.js 进程，也不将原件放入 release、Runner 状态目录、Agent workspace 或 PostgreSQL 大字段。
- **PostgreSQL 存控制信息**：上传者、项目/平台范围、分类、资料 ID、存储定位（逻辑存储别名 + 原件 Key，而非引用中写死 Bucket URL）、大小与 SHA256、解析/审核状态、版本和权限。活动数据库仍使用块存储，不挂载 OSS 作数据库目录。
- **索引另做容量规划**：提取后的正文、页码/文件偏移与片段索引需要独立容量预算；向量索引并非 8 GB 原件的固定小比例。先按样本统计可提取文本量，再决定 PostgreSQL 全文索引、向量库或混合检索。当前小型关键词检索实现不能直接扫描 8 GB。
- **上传方式**：待配置最小权限 RAM/STS 角色后，浏览器对指定批次前缀分片、断点续传直传 OSS。长期 Access Key 只允许留在受限服务端环境，不进入浏览器、仓库、日志、URL 或交付包。仅返回当前用户当前批次可用的短期凭证。Bucket 的 CORS 只允许实际站点源与所需方法/响应头。

## 导入闸门

1. 本地只读盘点。`node --import tsx scripts/knowledge-corpus-preflight.mjs <资料目录>` 输出体量和类型计数；加 `--hash` 流式计算去重哈希；如需清单，加 `--output /private/tmp/knowledge-manifest.json`，采用只创建新文件及 0600 权限。不会上传或索引。脚本不跟随符号链接，不读取隐藏文件、常见密钥文件，不自动解压归档。清单包含相对文件名，应按资料敏感级别保管。
2. 按类型分流：Markdown/文本/源码先抽正文；PDF 判断文字页或扫描页，后者才走 OCR；图片、EDA 工程使用专用解析；ZIP/7z 等先隔离检查压缩包内容和展开比，不自动解包。不支持的二进制先只记录元数据，不能以“已入索引”展示。
3. 后台按批次限速处理，先校验服务端从 OSS 读取到的大小/哈希，再做解析、切分、敏感信息扫描、质量与来源校验。失败记录可重试而不覆盖已发布版本；未完成分片和暂存对象设生命周期清理策略。
4. 片段保留原件 ID、版本、页码/字符偏移、哈希和审核状态；只把已发布、当前用户有权访问的片段送入方案 Agent。检索结果展示资料来源与未命中状态，撤回发布后新任务不再检索它。先以小样本评估召回、误召、响应时延和索引体量，再扩大批次。

## Bucket 选择与迁移约束

- 首阶段使用现有 **Store Dataset Bucket**，不使用同一份接入文档中的 App Store Bucket。实际 Bucket 名只放受限服务端配置 `OSS_KNOWLEDGE_BUCKET`；仓库、前端、检索引用和对外报告不硬编码真实名称或长期密钥。上传角色只允许操作知识前缀；不得为知识导入对整个共享 Bucket 套用删除型生命周期、公开读策略或覆盖旧对象的规则。
- 若以后新建知识专用 Bucket，保持资料 ID、版本、内容哈希与 Object Key 不变。迁移时先冻结或双写受影响批次，逐对象复制并从目标 Bucket **重新读取校验大小与 SHA256**；确认角色权限、CORS、生命周期与索引引用仍正确后，才原子切换服务端存储映射。保留旧 Bucket 回滚窗口，禁止按“复制成功”直接删除旧对象。
- 内容和切分规则不变时，可以沿用已有片段及索引引用；若重新解析、重新切分或源文件校验不一致，就必须重建对应索引。迁移程序、存储定位表、双写和校验尚未实现，这里是后续实施约束，不表示现已可迁移。

## 后续仍需确定的非敏感信息

- 需核验所选 Bucket 的地域、私有性、与云服务器是否同地域；准确的站点 Origin；计划允许谁上传（首版建议仅管理员/开发者），以及每批/每人容量与并发上限。
- 最小权限上传角色的 **RAM Role ARN**、STS AssumeRole 授权及 Bucket CORS。现有 `OSS-Access.md` 含长期凭据，但不等于已配置短期上传角色。不要在聊天里再发送 Access Key/Secret；由负责人在阿里云控制台及服务器受限配置中设置。
- 8 GB 资料的格式占比、文件数、是否包含扫描 PDF/原理图/PCB/固件和版权或个人信息。没有样本前不能给出准确 OCR、索引大小与费用预算。

`node --import tsx scripts/check-knowledge-oss-readiness.mjs` 只列网页直传所需配置的缺失项，不回显 Bucket 或密钥，也不访问 OSS。本次私有 CLI 上传与网页 STS 直传是不同通道；启用后者之前仍需在隔离环境验证角色最小权限、CORS、分片中断恢复、跨用户隔离和账单告警。

## 与现有版本的边界

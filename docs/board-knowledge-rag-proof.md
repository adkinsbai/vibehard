## 首批范围

`scripts/import-board-knowledge.mjs` 只读取 9 个明确列出的源文件：RV1106 的硬件参考、摄像头/YOLO 实测和 RV1106 v2.0 数据手册；RV1126B 的 BOARD、PINMAP、PITFALLS、硬件参考、软件开发基线和 RV1126B v1.1 数据手册。源文件来自用户给出的两个本地目录，不自动跟随其他目录或符号链接。原理图 PDF 仅从前次清单中列为候选，首批不把图纸文本当作已验证的连线事实。

运行时按文件 SHA256、PDF 页码和段号保留来源。Markdown 直接切分；PDF 使用 `pdfplumber` 逐页抽文字，空页不入检索。每条正文最多 3500 字，带少量重叠；目录路径、压缩包、固件、模型、构建产物、日志和 SDK 整树不会自动导入。疑似密钥内容使整个批次失败，而不是静默脱敏后发布。PDF 文字抽取不等于表格、封装或原理图视觉验收。

本机干跑：9 个源文件生成 **95 条**小型平台知识条目；批次 SHA256 为 `7373380e3214781ed7967b29f27ad087de875290d7a782c1b861bc11998abb84`。`RV1106 GC1084 摄像头 ISP 和 YOLO` 命中摄像头实测、硬件参考与数据手册；`RV1126B eMMC GPIO 硬件设计` 命中数据手册、板卡档案、硬件参考和引脚台账。检索每次最多 5 条、约 6000 字，单一导入文件最多占 2 条参考，不把整个手册塞进模型请求。当前方法是 **有界关键词/中文二字词检索**，还不是向量召回或语义重排；测试已验证命中片段进入实际模型请求体的构造逻辑，但未发出真实模型请求。

## 导入边界

CLI 默认为只读干跑。数据库写入模式必须明确指定 `--apply`、现有管理员/开发者 UUID、目标数据库名以及干跑得到的批次哈希，并从受限环境提供 `DATABASE_URL`；它在单事务中检查角色、200 条上限、稳定 ID 和现有版本一致性。重跑相同批次跳过已存在条目；同 ID 内容有变化即中止，不覆盖已发布资料。审计记录标记 `manualReview: false`。网页普通提交/审核 API 未被绕过或降权。页面与模型提示词只称“已发布”，不谎称本批已人工审核。

首批使用现有 `shared_knowledge` 小型正文表；不是 8 GB 全量导入架构。实际 8 GB 原件仍计划放私有 OSS，PostgreSQL 存元数据与索引，见 [OSS 方案](oss-knowledge-import.md)。目前 CLI **没有**上传 OSS 或持久化原件；来源是相对路径与哈希，云端部署前必须解决原件托管/可查看问题。厂商 PDF 的存储与展示许可尚未独立核验，当前只作为内部验证候选。

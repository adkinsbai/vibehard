# 四项修复与真实 BOM 分项评审

2026-09-28。评审对象是独立工作树 `codex/audit-boundary-fixes`，不是当前生产发布。结论为**可以分别提交代码供 Git 评审，不代表可以跳过生产发布闸门**。工程导入已暂缓，不在这两项内。

## 一、四项修复

基线提交 `473d794` 已在同名 GitHub 分支；本次评审补丁为本地提交 `6f0933c`。核查了方案 Worker 的认领/阶段/失败写入期限与连接回收，多索引集合的旧批次保留、来源停用与回滚，同原件批次不同构建版本的目录和选择，以及登录 Cookie 与当前密码哈希绑定。没有发现越权放行或把生产指针直接改写的路径。失败记录在数据库不可写时仍可能依赖既有租约转为 `LEASE_EXPIRED`，这已记录为设计边界，不会自动重发付费模型请求。

评审补充发现：受控索引 manifest 原先接受极大的正整数 `version`；JavaScript 会把 `1e21` 转成科学记数法目录名，后续 build ID 参数校验无法选择该登记。现限制版本为 `1..1_000_000`，增加拒绝用例。生产当前正常版本不受影响。这项和 Worker 的跨 SSH 时序回归补充作为四项修复的后续独立提交，不混入 BOM。

旧 Cookie 在敏感 API 与服务端知识页面被拒；客户端静态工作台外壳可能先显示，再因 API 401 呈现失败。它不能读取受保护数据，但若希望立即跳回登录页，需要以后另做 UX 改进。正式上线还需验证旧会话、真实 Worker 任务和成套索引程序/指针回滚。

## 二、真实 BOM

页面移除假库存、假下单和静态器件。服务端先检查项目归属，再只读已完成方案的持久化结果；CSV 对模型控制的文本做表格公式转义。页面与导出均明确价格是模型估算，不宣称供应商实时报价或封装已验证。

真实 BOM 的独立本地提交为 `c03a635`，不包含四项修复的评审补丁。

评审补充发现：原 CSV 路由总是重新读取“最新方案”，若页面展示后另一个方案完成，下载内容可能与页面不一致。现在页面将所示 `designId` 带给 CSV 路由，服务端在同一用户、同一项目、已完成结果条件下精确查询；不存在的方案返回 409，不会悄悄下载别的版本。追加接口、数据库及真实 HTTP 回归。

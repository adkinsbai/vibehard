# 平台功能验收矩阵

更新：2026-09-28。本表以 `codex/audit-boundary-fixes` 的代码、模块说明和 9 月 27 日生产验收记录为基线；它不是持续监控报告。生产进程存活不能替代真实用户闭环。本轮暂不优化 EDA 与原理图识别的识别/设计精度，但仍列出其输入、结果和已知边界。

状态：`已验证` 表示有相应真实链路的近期证据，不保证长期可用；`部分` 表示只有链路的一部分真实；`演示` 表示关键步骤使用预设或模拟数据；`待复测` 表示功能存在但本轮未独立验收。每一项必须同时验证正常路径、普通失败、越权、刷新恢复和可回滚性，才能标记为可用。

## 实施批次与统一证据

1. **四项修复验收**：Worker 锁等待和取消、多个知识索引同时检索及回滚、同批次新版本、改密旧会话撤销。隔离数据库与云端候选证据见 [候选验收记录](./audit-bom-candidate-20260928.md)；正式发布仍须代码评审、备份和独立回滚。数据库完全不可写时允许任务留 `running` 直到租约到期，但必须及时回收 Worker、关闭连接，不得自动重发付费模型请求。
2. **项目工程导入（暂缓）**：用户 9 月 28 日决定先不做工程导入。现网没有该上传/落地闭环；不把预检代码或演示按钮混入本轮候选。以后重新启动时仍须明确输入格式、项目归属、路径与链接防护、受限进程原子落地、审计和回滚。
3. **知识批量入库**：沿用私有 OSS 原件、不可变清单、自动筛查和受限索引；增加可审计的管理员操作入口，但不绕过现有隔离评估和激活/回滚门槛。
4. **真实 BOM**：只读取用户有权访问的已完成方案；导出实际文件。模型估价与供应商实时报价必须分开。
5. **下一阶段设备闭环**：以连接泰山派的现场电脑作 USB 节点，不绑定某台 Mac mini；逐项验收构建、烧录、串口和失败恢复。

每项证据记录：代码提交、候选版本、测试命令和结果、真实用户操作截图或 HTTP 记录、项目/批次 ID、错误码、回滚点。禁止把单次模型成功、静态截图或进程 `active` 单独作为“可用”结论。

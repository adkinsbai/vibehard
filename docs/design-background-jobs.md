# 方案后台任务（本地开发，未上线）

## 任务确认与编辑边界

2026-09-20 用户确认：点击生成自动创建或关联 Agent 项目、保存需求、后台生成、方案归档；确认新增任务表及项目归属校验。本轮仅本地实现和测试，不迁移或发布生产。

允许修改：方案页面/API、项目内方案入口、独立方案任务存储/处理器、新增数据库迁移、相关测试及说明。保持认证机制、角色权限、知识审核、Runner/Gateway 协议、设备和现有工作区文件不变。

## 设计

- PostgreSQL 事务同时保存项目与任务。请求幂等键防止网络重发创建重复项目；关联已有项目必须属于当前用户。
- 独立 `design-worker` 拉取持久队列，不使用浏览器长连接或 Next.js 请求生命周期运行模型。网页只提交和查询；关闭网页不取消任务。
- 全局最多 1 个方案模型请求，每用户最多 1 个活跃方案任务，队列最多 20 个。单次模型调用限制 90 秒，任务执行租约 120 秒，排队上限 10 分钟。进程异常后任务明确失败，不自动重放可能已计费的请求。
- 成功结果与原始需求保存在所属项目的方案记录中，可查看与下载 Markdown；不自动发布知识库，不写 Runner 工程目录，不声称生成了可编译固件。
- 失败保留需求、项目与错误。显式重试产生同项目的新任务，旧记录保留。方案页与项目入口均能恢复状态。

## 文件与启动

- 表：`design_jobs`，迁移 `drizzle/0005_design_jobs.sql`。仅新增表/外键/索引，不重写现有项目、账号、模型或知识数据。
- API：`POST /api/design` 改为 `{ requestId, requirement, projectId? }` → `202 { job }`，不再返回 NDJSON；`GET /api/design` 分页记录，`GET /api/design/:id` 查询，`GET /api/design/:id/download` 下载。所有 API 按当前用户检查项目/任务归属，管理员也不能借此读取他人方案。
- 页面：`/app/design`，项目入口 `/app/agent/:projectId/designs`。Agent 工作台“方案记录 · 进度与下载”链接可进入；方案页“进入 Agent 项目”会选中对应项目。
- `node scripts/build-services.mjs` 生成 `dist/services/design-worker.cjs`；处理器与平台使用同一数据库及 `SESSION_SECRET`，按任务读取已保存的模型配置。不能只更新前端，不启动处理器。
- `deploy/systemd/vibehard-design-worker.service` 是待部署模板；发布时核实 Node 路径、替换为版本化 release 路径。动态低权限用户、不写工程目录、256 MB 内存与 50% CPU 上限。不要重启 Gateway 或更改 Runner 凭据。
- 未配置数据库时明确返回 503，不以内存假装持久化。处理器宕机期间查询会将超过 deadline 的任务显示失败；恢复后清理租约，不自动重放模型请求。
- 全局串行限制仅针对方案生成，不替代 Agent/原理图各自的配额。需求和结果保存在项目的数据库记录中，不自动注入 Agent 对话上下文或工程 ZIP。

# 原生模块包受控入库与发布门槛

本阶段把原生 KiCad 模块从测试样板分离为一个**全平台共享、按版本不可覆盖**的目录。当前没有工程师签审的正式模块，公开目录应为空。`sample.led-indicator` 继续只用于软件链路回归，不能通过入库或发布门槛。

## 接口与数据

- `POST /api/eda/modules`：仅管理员/开发者提交 `{manifest, filesBase64}`，总请求最大 3 MB，解码原件最大 2 MB。可提交清单为 `pending-review` 的候选；拒绝 `software-fixture` 与 `sample.*`。逐文件校验安全相对路径、SHA-256、端口位置；生产环境通过带管理令牌的本机回环 `POST /v1/modules/verify` 在隔离 KiCad 9 环境导出真实网表，再校验端口、受支持的原理图符号、PCB 封装、内部网络和走线。提交后状态为 `pending`，任何同 ID/版本再次提交都拒绝。服务端角色复查、同源检查、限流、数据库审计适用。
- `GET /api/eda/modules/review`：仅管理员/开发者列出待审版本；加 `?id=<UUID>` 可取得特定包的不可变清单和原始文件，以便人工核对。原始文件绝不由公开目录返回。
- `POST /api/eda/modules/review`：仅管理员/开发者且账号 UUID 在服务端 `EDA_HARDWARE_REVIEWER_IDS` 名单内者可发送 `{id, reviewReference}`。名单未配置或格式无效时**一律无法发布**；提交者不能自审。审查时再次从已存原件运行 KiCad、编译模块定义并比对提交时的结果与包哈希。若原清单已声明审核来源，审核编号须与之匹配；`pending-review` 候选则由独立审核人新填审核编号。迁移 `0008` 还在数据库层拒绝更改源文件/定义/版本，并限制未经双人审核的 `published` 状态。管理员/开发者角色本身不等于硬件工程师资质；名单身份与签审报告仍须由发布负责人线下核实，审核编号不能自证签名。
- `GET /api/eda/modules`：登录用户只收到已发布模块的受控定义，包含固定 `moduleId`、`version`、`sourceSha256`、端口、器件和 PCB 内部网络/走线；没有原始文件或待审核包。Agent 每个请求从数据库取已发布目录并使用该目录检查提案，不能使用软件样板。浏览器也从此接口载入目录，编辑、保存、检查和导出均使用请求作用域的已发布定义；绝不依赖用户提交的模块定义决定可用性。

模块包目前仅支持现有受控 KiCad 9 器件库、单页原理图、双层矩形 PCB、无过孔/铺铜/弧线，且内部走线不得跨外部端口网络。超出能力时明确拒绝，不能静默丢失原生内容。单个包超过 2 MB 要改为受控对象存储，不能扩宽数据库 JSONB 入口来绕开限制。迁移只随评审后的版本化 release 进入隔离测试库和生产库，本阶段没有写生产数据库。

## 当前案例库与正式模块缺口

本地项目及 `Documents` 下能找到的 KiCad 原生文件只有软件样板、新增自动布线测试夹具，以及几个独立的个人单页原理图；没有可核对为案例库正式来源且带 PCB 的同版本原生模块包。为验证 `pending-review` 生命周期，另存了 [`led-indicator`](eda-module-candidates/led-indicator/README.md) 候选包；它明确来自软件样板而非案例库原件，BOM 和电气参数仍待核实。仓库中已有的板卡目录与 OSS 索引记录主要用于来源/正文检索，不能把 PDF/OCR 文本逆推出可编辑的 PCB 原件。按用户提供的私有 OSS 接入文档只读尝试读取既有映射清单时，接入点公网域名在本机 DNS 不解析；区域通用端点返回 403，未读取到清单。因此**不能断言 OSS 内没有原生 KiCad/PCB**，也不能用仓库测试夹具冒充现有案例。

首个候选需要确认：原理图、PCB、工程及库表同一修订；器件厂家/料号、额定值及电源边界；端口电气定义和适用板卡/版本；原始设计授权；工程师签审报告及例外项。软件可先验证结构、KiCad 网表、ERC/DRC 和导入回读，但这些检查不能代替硬件功能、绝缘/热/EMC、制造或实物审核。正式签审材料尚未提供时，不发布模块，也不宣称“正式硬件设计可用”。

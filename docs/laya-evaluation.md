# Laya 对器件选型与 RAG 的适用性评估

后续状态：2026-09-25 已按用户要求完成本地独立部署及合成样例实测，见 [部署说明](../laya/README.md)。下文“未运行”为本次部署前的评估时点；硬件领域质量和平台端到端收益仍未验证。

评估日期：2026-09-25。依据：当日上游公开文档/源码、本地工作区代码和最近发布记录。未安装/运行模型、未测平台性能、未复测生产。本文件为建议，未实施集成。

## 结论

值得做小规模对照实验，优先用于召回后的资料相关性排序、器件证据预筛和缺失资料分流；不能直接裁决某器件能否满足整机需求。用户设想可落为：需求 → 候选及证据召回 → 硬约束检查与 Laya 语义预筛 → 详细核验 → 方案/BOM。

## 上游证据

- 输入文本/JSON 与题目，输出 choice、score、noul 等固定类型决策；不是器件数据库或完整 RAG 系统。[项目说明](https://github.com/NandhaKishorM/laya)
- 源码采用双向编码器和决策头，`predict_batch` 可批量处理多个状态。没有自由文本生成，不代表不会分类错误或可以自行提供来源解释。[模型构造](https://github.com/NandhaKishorM/laya/blob/main/laya/common.py)、[推理实现](https://github.com/NandhaKishorM/laya/blob/main/laya/agent.py)
- 项目自报 RAG 片段相关性准确率最高 0.657，不能外推为硬件选型准确率。T4 多语言单题约 32.8 ms；4 核 EPYC CPU 约 193 ms，CPU 50 题约 11.157 s。均非本平台实测。[基准及限制](https://github.com/NandhaKishorM/laya/blob/main/BENCHMARKS.md)
- 多语言模型默认 1,024 tokens，可显式扩大到 8,192；推荐短参数卡和证据片段，不建议在线反复输入整本手册。[模型卡](https://huggingface.co/convaiinnovations/laya-multilingual)
- 提供 Python HTTP 示例和 ONNX TypeScript 实现。可先用独立常驻 Python 服务，TS 路径另做模型导出与兼容性验证。[HTTP 示例](https://github.com/NandhaKishorM/laya/blob/main/examples/server.py)、[TS 文档](https://github.com/NandhaKishorM/laya/blob/main/laya-ts/README.md)

## 推荐的数据准备和在线流程

离线：原始手册/官方资料解析 → 提取器件参数卡 → 审核发布 → 型号精确索引与关键词/向量索引。参数卡保留具体型号/封装、功能、供电、接口/电平、工作模式、功耗条件、温度、限制、页码/表格、文档版本和哈希。统一单位，区分推荐工作条件、绝对最大额定值、典型值和保证值。Laya 可辅助分类，但不替代参数抽取与审核。

在线：

1. 需求拆为功能块、硬约束和偏好；先区分必须直接连接还是允许转换电路。
2. 从有权限的正式正文中召回候选；保留型号精确匹配，后续评估混合召回以覆盖同义表达。
3. 对可信结构化字段用程序检查电压、接口、电流等条件。只在明确违反硬约束时排除；字段缺失、工况不同则未知。
4. Laya 批量评估“指定需求/约束 + 一个候选短参数卡/片段”，预测相关性以及支持/冲突/信息不足。
5. 高优先级及未知项继续检索手册，核对脚注、工作条件、引脚复用和系统预算。
6. 大模型组合方案，程序检查跨器件约束，输出 BOM、证据引用和待确认项。

可以从召回 30–50 个、详细核验 5–10 个开始试验；数字为实验参数，非已验证容量。第一阶段只记录排序，不据此删除候选。重排不能找回召回阶段已经漏掉的器件。

## 决策题目与例子

不要把上百器件放进同一个 choice 选唯一最佳。对每个候选复用题目模板，围绕其承担的功能块判断，不能要求一个器件满足整机全部功能。

- 这段资料是否与指定功能块的选型相关？
- 对指定约束，资料提供支持证据、冲突证据，还是信息不足？
- 下一步应优先核查供电、接口、功耗条件，还是封装/引脚？

显式设置 `supported` / `contradicted` / `unknown`，逐项约束判断。它们是证据分类预测，不直接映射为最终批准/排除。

假设需求为“3.3 V 直接供电、I²C、连续 100 Hz 采样、平均电流不超过 50 μA”：

- 虚构器件 A 推荐供电 1.7–1.9 V：程序发现直接供电冲突；允许加稳压器时另评估组合方案。
- 虚构器件 B 支持 3.3 V/I²C，但只给休眠电流 1 μA：连续采样功耗仍未知，不能通过。
- 虚构器件 C 缺电流测试条件：保留候选，查工作模式及采样率对应证据。

Laya 帮助确定哪些文字值得核查、哪里缺证；数值比较、单位换算和电源/带宽预算用程序完成。器件分别满足条件仍不证明组合后无冲突。

## 接入约束

- 建议独立常驻 Python 服务、有界批量请求、预加载固定多语言模型并记录 revision；中英文混合卡片单独评测。
- 模型只接收已授权候选，不参与权限裁决、正式发布审批或设备操作授权。
- 证据引用来自检索记录：保留来源、版本、SHA256，增加实际页码/表格/chunk ID，不能让分类器编造引用。
- 源码中不同题型的 `confidence` 定义不一致；有 `answer_confidence` 和类别概率可用，但仍需独立硬件数据校准，不能把 0.9 理解为器件有 90% 概率可用。[字段实现](https://github.com/NandhaKishorM/laya/blob/main/laya/agent.py)
- 服务不可用、超时、截断或无法判断时保留原召回结果/继续详细核验，不能当不适用。
- 缓存键包含需求/约束、证据版本、模型 revision 和题目版本；限制作用域，命中前重新核对当前权限和发布状态。

## 性能与验证建议

当前关键词匹配不需要神经网络，直接叠加 Laya 会增加推理开销。只有减少后续详细检索、模型调用、输入长度或返工，才可能降低总耗时。当前最多 5 个片段，不应假设上下文压缩有巨大收益；模型生成时间及供应商网络/排队超时也不会自动解决。

先离线对照，再接影子流量：

1. 选 30–50 份有原始证据的手册，人工标注约 300–500 组需求/约束—候选—证据，覆盖支持、冲突、缺失与边界数值。仅为起步样本量。
2. 按芯片家族/手册划分训练、校准、测试集，避免近重复片段泄漏，阈值与微调不使用最终测试集。
3. 对照现有关键词检索、混合召回 + 专用重排器、相同召回 + Laya；统一权限、证据范围与候选输入。
4. 测适用候选 Recall@K、误删率、不可用候选误放行率、未知识别、排序质量、端到端 P50/P95、生成 tokens、吞吐和资源消耗。
5. 可暂设 Recall@K ≥ 98%、端到端 P95 降低 ≥ 20% 为讨论目标，需同时报告样本数和置信区间；小样本达标不能证明全部器件类别均适用。

对照证明收益后逐步启用排序，硬排除以有证据的规则检查为主。若专用重排器更优，就采用该方案。

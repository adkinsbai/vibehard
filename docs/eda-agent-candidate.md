# 从已保存原理图创建 Agent 候选

在 `/eda` 选择工程后，点“读取当前已保存原理图”。Agent 只读取该工程磁盘上的单页原理图和 KiCad 网表，并将快照的工程 ID 与原理图 SHA-256 绑定到当前草稿。提案审阅区列出器件、参数、网络引脚等电路变化及修改命令；变化列表最多显示前 12 项和剩余数量。用户决定是否将提案加入草稿。

创建候选时，面板会对最初读取的工程 ID 再请求一次快照。若已保存原理图的 SHA-256 不同，显示 `409 冲突` 并保留草稿，用户需重新读取和审阅。快照缺少有效哈希或复核请求失败时也不会创建候选。切换左侧选中的工程不会改变草稿绑定的源工程。

复核通过后，现有创建流程新建并打开独立的 KiCad 工程；新工程名称标记“候选”并包含完整源工程 ID。源工程及其已保存文件不会被覆盖。新 PCB 根据草稿重新生成，仍需检查 ERC、器件参数、走线和硬件约束。

这是客户端在创建前进行的冲突检查。项目创建接口尚无原子性的源快照前置条件，因此复核和创建之间仍可能发生源文件变化；工程名也只是可见的来源标记，不是数据库里的结构化版本关系。当前流程不支持对已打开的原生 KiCad 工程就地修改，也不会保留源 PCB 的现有布局。
